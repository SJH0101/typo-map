## 1. 방식 A — `detect_surya.group`

### 입력

- **실제 파이프라인** (`measure_corpus.measure_items`): Surya `DetectionPredictor` 결과의 `b.bbox` (실수 네 개 `[x1, y1, x2, y2]`) 목록 → `detect_surya.boxes_norm(lines, (W, H))` → 안에서 `group(lines)`.
- **묶기 채점기** (`eval/group_score.py`): 같은 `bbox` 목록을 파일(`~/.typo-mcp/group-lines.json`)로 두고 `group()` 을 직접 부른다.
- **쓰는 것은 상자 네 좌표뿐이다.** Surya 의 폴리곤 · 신뢰도 · 글자 내용 · 이미지 픽셀은 보지 않는다.
- **전처리.** 좌표를 정렬하고(`_norm`), 넓이 < `MIN_AREA` (200 px²) 인 상자는 버리고, (y1, x1) 순으로 정렬한다.

### 판단 조건 (실제 코드)

```python
while moved:
    moved = False
    gx1 = min(b[0] for b in g); gx2 = max(b[2] for b in g)
    gy2 = max(b[3] for b in g)
    gh = float(np.median([b[3] - b[1] for b in g]))
    for j, b in enumerate(L):
        if used[j]:
            continue
        bh = b[3] - b[1]
        if not (H_RATIO[0] <= bh / max(gh, 1) <= H_RATIO[1]):
            continue
        if min(gx2, b[2]) - max(gx1, b[0]) <= X_OVER * min(gx2 - gx1, b[2] - b[0]):
            continue
        if not (Y_GAP[0] * gh <= b[1] - gy2 <= Y_GAP[1] * gh):
            continue
        g.append(b); used[j] = True; moved = True
```

**묶음 쪽 값 (반복을 시작할 때 한 번 계산).**
- `gx1` · `gx2` = 묶음 상자들의 왼쪽 끝 최솟값 · 오른쪽 끝 최댓값
- `gy2` = 묶음 상자들의 **아래 끝 최댓값** (묶음의 가장 아래)
- `gh` = 묶음 상자 높이 (y2 − y1) 의 **중앙값**

**세 조건이 비교하는 것.**

| 상수 | 분자 | 분모 · 기준 | 통과 조건 |
|---|---|---|---|
| `H_RATIO = (0.60, 1.70)` | 후보 상자 높이 `bh` | 묶음 상자 높이 중앙값 `gh` | 0.60 ≤ `bh / gh` ≤ 1.70 |
| `X_OVER = 0.15` | 겹친 폭 = min(`gx2`, 후보 x2) − max(`gx1`, 후보 x1) | 0.15 × min(묶음 폭 `gx2 − gx1`, 후보 폭) | 겹친 폭이 기준을 **넘어야** |
| `Y_GAP = (−0.40, 1.60)` | 틈 = 후보 상자 윗끝 `b[1]` − 묶음 아래 끝 `gy2` | `gh` 의 배수 | −0.40·`gh` ≤ 틈 ≤ 1.60·`gh` (음수는 상자가 물린 것) |

셋 다 통과하면 묶음에 넣고 반복을 다시 돈다. 한 반복 동안 아무것도 안 들어오면 묶음이 확정되고, 쓰지 않은 가장 위 상자에서 새 묶음을 시작한다.

**줄 상자 높이는 x높이가 아니다.** Surya 상자에는 어센더 · 디센더 · 검출기 여백이 들어 있다. 그래서 같은 x높이 12px 본문 줄이 줄에 든 글자에 따라 17~28px 로 나온다 (069). `H_RATIO` 와 `Y_GAP` 의 분모가 모두 이 높이다.

### 이 구조에서 나오는 성질 (코드 읽기 + 069 에서 확인)

1. **짝 비교가 아니다.** 후보는 판에서 아직 안 쓴 **모든** 상자다. 바로 아래 줄이 아니어도 된다.
2. **틈의 기준이 움직인다.** 틈은 «묶음의 가장 아래 끝» 에서 재므로, 묶음이 자라면 기준이 내려간다. 한 번 거절된 후보도 나중 반복에서 들어올 수 있다 (069 #8: 반복 1~3 거절, 반복 4 에서 합침).
3. **한 반복 안에서는 묶음 값이 고정이다.** 같은 반복에 들어온 상자는 `gy2` · `gh` · 폭에 다음 반복부터 반영된다.
4. **`gh` 가 중앙값이라 묶음이 자라며 크기 판정이 뒤바뀐다.** 가운데 줄을 건너뛰고 그 아래 줄을 삼킬 수 있다 (069 A5, 4절 끝).
5. **결과는 순서에 달려 있다.** 위에서부터 씨앗을 잡고, 먼저 잡힌 묶음이 가져간 상자는 다른 묶음에 가지 않는다.

### 문턱과 근거

- **값.** `H_RATIO (0.60, 1.70)` · `X_OVER 0.15` · `Y_GAP (−0.40, 1.60)` · `MIN_AREA 200`.
- **기록.**
  - `d7a1250` (2026-08-31, «검출을 Surya 로 갈아끼운다») 에 지금 값 그대로 처음 들어왔다.
  - 그 커밋 본문과 `docs/surya_switch.json` 에 **값을 고른 스윕이나 검증 기록이 없다.** 코드 주석은 «전부 옛 detect.py 가 쓰던 것과 같은 생각이다» 라고만 적었다.
  - `docs/surya_switch.json` «아직 안 된 것»: «호프만 장당 3.3 블록은 적어 보인다. 묶기가 과하게 붙였을 수 있다 — 눈으로 확인 안 했다».
- **옛 `baseline/detect.py` 의 대응 상수는 정의부터 다르다.**
  - `GAP_RATIO = 1.5` «행간이 중앙값의 1.5배 넘으면 자름» — **베이스라인 간격 ÷ 간격 중앙값**을 본다. A 는 상자 틈을 본다.
  - `SIZE_RATIO = 0.25` «활자 높이가 25% 넘게 변하면 자름» — 대략 0.8~1.33배. A 는 0.60~1.70배다.
  - 이 둘에도 스윕 기록이 없다. 같은 파일의 `COL_FRAC` · `STRATA_RATIO` · `COL_GAP_FRAC` · `BAND_STEP` 에는 스윕 기록이 있다.
- **처음 정답에 댄 기록.** A 문턱을 합성 정답에 처음 댄 것은 묶기 비교 240장 (`docs/group_result.json`) 이다. 문턱은 바꾸지 않았다.

## 2. 방식 C — `group_gap.group_gap`

### 입력

같은 Surya 줄 상자 목록과 흑백 이미지(`gray`). 인자로 `tau` (기본 1) 와 `pad_rule` (`'fixed'` | `'neighbor_half'`) 을 받는다.

### 판단 순서와 조건 (실제 코드)

**① 먼저 잰다.** 줄 상자마다 `region.measure(gray, box, pad)` 로 그 상자 안 잉크의 베이스라인 · x높이 · 가로 범위(`x_starts` · `x_ends`)를 얻는다. 잰 줄 하나가 **요소** 하나다. pad 는 `'fixed'` 면 위아래 3px, `'neighbor_half'` 면 이웃 줄 상자까지 틈의 절반(최대 3px)이다. 한 상자에서 두 줄이 재지면 요소도 둘이다.

**② 세로 사슬 — 앞 요소 찾기.**

```python
if e['b'] - p['b'] <= tau:
    break                     # 여기부터는 같은 행이거나 아래다
ov = _xover(e, p)
...
ov = min(a['xe'], b['xe']) - max(a['xs'], b['xs'])
return ov if ov > DS.X_OVER * min(a['xe'] - a['xs'], b['xe'] - b['xs']) else None
```

- 앞 요소 = 베이스라인이 **τ 넘게 위**에 있고, 가로 겹침이 좁은 쪽 폭의 `X_OVER` 를 넘는 요소 가운데 가장 가까운(가장 아래) 것.
- 한 앞 요소를 여럿이 가리키면 겹침이 큰 하나만 잇고, 나머지는 새 사슬을 시작한다.

**③ 간격 run.**

```python
while j < len(gaps) and max(gaps[i:j + 1]) - min(gaps[i:j + 1]) <= tau:
    j += 1
```

사슬의 베이스라인 간격 목록을 앞에서부터 읽어, 간격들의 최대 − 최소가 τ 이하인 동안 한 run 으로 늘린다.

**④ 블록 — 패턴 run 과 공유 요소.**

```python
pat = [r for r, (s, e) in enumerate(rs) if e - s + 1 >= 2]
...
same1 = abs(x - els[ch[pos - 1]]['xh']) <= tau
same2 = abs(x - els[ch[pos + 1]]['xh']) <= tau
```

- 간격 2개 이상인 run (요소 3개 이상) 이 **패턴 블록**이다.
- 이웃한 두 패턴 run 이 경계 요소 하나를 함께 덮으면, x높이가 τ 안에서 같은 이웃 쪽에 붙인다. 둘 다 같거나 둘 다 다르면 남긴다.
- 어느 패턴 run 에도 안 든 요소도 남긴다.

**⑤ 줄 소속과 A 폴백.** Surya 줄은 그 줄의 요소가 가장 많이 든 패턴 블록에 속한다 (그 수가 남은 요소 수 이상일 때). 아니면 «남은 줄» 이 된다. 남은 줄에만 `detect_surya.group` 을 그대로 부른다.

### τ 가 비교되는 세 자리

| 자리 | τ 와 견주는 값 |
|---|---|
| 사슬 (②) | 두 요소의 **베이스라인 차**. τ 이하면 «같은 행» 으로 보고 앞 요소가 될 수 없다 |
| run (③) | run 안 **베이스라인 간격들의 최대 − 최소** |
| 공유 요소 (④) | 경계 요소와 이웃 요소의 **x높이 차** |

### 문턱과 근거

- `TAU = 1` — 사전등록 `docs/group_preregister.json` 수정 1 (`ef0cf65`). 정수 베이스라인마다 ±0.5px 양자화라 간격에는 ±1px 이 실린다. `check_layout` «블록 내 행간 일정» 과 같은 수다.
- `X_OVER = 0.15` — A 의 상수를 그대로 읽는다. A 의 근거 기록이 없다는 점을 그대로 물려받는다.
- pad — `region.PAD = 3` (기존). `'neighbor_half'` 는 `docs/measure_pad_preregister.json` (`2eac80c`) 로 검증해 채택했다 (`ab59911`). 묶기 비교 240장 세트는 `'fixed'` 로 고정.
- 패턴 최소 3줄 — 간격이 둘은 있어야 «같은가» 를 볼 수 있다는 정의 (사전등록 수정 1).

## 3. 두 방식이 «간격» 이라고 부르는 것

| | 무엇의 거리인가 | 무엇으로 판단하나 | 줄에 든 글자의 영향 |
|---|---|---|---|
| **A** | **Surya 상자 가장자리 사이.** 후보 상자 윗끝 − 묶음 가장 아래 상자의 아래 끝. 잉크 상자도 베이스라인도 아니다 | 그 틈이 묶음 상자 높이 중앙값의 몇 배인가 (≤ 1.60 이면 붙인다). **«얼마나 벌어졌나»** | 크다. 어센더 · 디센더 유무와 검출기 여백이 상자 높이와 틈을 둘 다 바꾼다 |
| **C** | **잰 베이스라인 사이.** 같은 사슬의 이웃 요소 베이스라인 차 | 이웃 간격들과 같은가 (±1px). 크기로 나누지 않는다. **«앞 간격과 같은가»** | 작다. 베이스라인은 글자 몸통 바닥이라 어센더 · 디센더에 흔들리지 않는다 |
| 참고: 옛 `baseline/detect.py` | 베이스라인 사이 | 간격 ÷ 간격 중앙값 > 1.5 면 자른다 | C 와 같은 양을 비율 문턱으로 봤다 |
| 참고: 정답 JSON `pairs[].gap_px` | 베이스라인 사이 | — | C 와 같은 종류의 양이다. 잉크 틈 필드는 없다 |

**A 와 C 는 서로 다른 것을 본다.**
- **A** 는 «틈이 상자 높이의 1.6배 이하면 붙인다».
  - 안쪽 행간과 같은 틈이든 두 배 틈이든, 상자 높이 1.6배 안이면 구분하지 않는다.
  - 등크기 본문에서 틈 ≈ L·g − (상자 높이) 이다. 069 의 상자 높이 18~25px, g = 24px 로 어림하면 L 이 대략 2.0~2.6 이하일 때 붙인다. 등크기 2g 쌍의 병합률이 1 도 0 도 아닌 까닭이 여기 있다 — 경계가 줄에 든 글자로 흔들린다.
- **C** 는 «경계 간격이 안쪽 행간과 1px 만 달라도 가른다».
  - 대신 경계 간격이 안쪽 행간과 **같으면** (등크기 1g) 가를 정보가 없다.
  - 크기가 다른 블록 사이에서도 행간이 달라지면 간격 패턴이 바뀌어 가른다. 단, 두 run 이 요소 하나를 나누면 x높이로 소속을 정한다.
