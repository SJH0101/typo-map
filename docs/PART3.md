# 파트 3 — 짚는 일과 재는 일

파트 1 은 조판을 재고, 파트 2 는 활자와 그림을 가르려다 아홉 번 막혔다.
파트 3 은 그 앞에 있던 질문이다 — **무엇을 재야 하는지 누가 정하나.**

사람이 포스터 26장에 상자 130개를 손으로 그렸고, 처음으로 채점이 가능해졌다.
그 결과 파트 1 의 진단이 틀렸다는 것이 드러났다.

## 진단 정정 — 구멍은 묶기가 아니었다

인수인계 문서는 「블록 묶기가 가장 큰 구멍」이라고 적었다. 사람 상자로 채점하니
그렇지 않다.

    잡은 비율   78/130 = 60%
    과분할      28      ← 묶기 문제
    헛것        92      ← 도형을 글자로 잡음
    놓침        52      ← 검은 바탕의 흰 글자
    상자 수     프로그램 232 / 사람 130 = 1.78배

    디센더 모자람  중앙 +2px   ← 작다

묶기(과분할 28)보다 **무엇을 묶을지**(헛것 92 · 놓침 52)가 훨씬 크다. 그리고
디센더를 크게 빼먹을 거라 본 예상은 빗나갔다 — 잉크 범위는 대체로 맞는다.

## 경계를 실측했다

오페라하우스 두 점을 IDML 참조선과 대조했다.

    덩어리 찾기   VLM 6/6 맞음         ·  blocks.run() 은 17개·12개로 쪼갬
    상자 위치     VLM 여덟 변 중 일곱이 ±1px
    행간 재기     VLM +24% 편향(두 번 다) ·  boxmeasure 21.0px = 참조선
    정렬 판정     —                    ·  왼쪽 흩어짐 0.0 대 오른쪽 39.6px

오차가 무작위가 아니라 **한 방향으로 일정**했다. 세었다면 양쪽으로 흩어졌을
것이다. 시각 모델은 판면 안에서의 **관계**는 붙들지만 **절대 거리**는 못 붙든다.
조각(patch) 단위 요약이 상대 위치는 보존하고 절대량은 뭉개기 때문으로 보인다.

그래서 `boxmeasure.py` 를 따로 두었다. 상자를 받아 그 안만 재므로 헛것과 놓침이
구조적으로 생기지 않는다 — 잴 자리를 이미 받았기 때문이다.

## 배율은 이득이 없다

처음에는 포스터를 2배로 렌더해 넣었다. 근거 없이 정한 절차였고, 나중에
「알려진 배율로 렌더한다」를 방법의 조건인 것처럼 적었다. 재 보니 틀렸다.

포스터 3점 · 사람 상자 14개 기준.

    1배   맞은짝 13/14   내 상자 15   F1 0.90   맞은짝 IoU 0.821
    2배   맞은짝 13/14   내 상자 15   F1 0.90   맞은짝 IoU 0.812
    4배   맞은짝 12/14   내 상자 17   F1 0.77   맞은짝 IoU 0.825

**1배와 2배가 같고 4배는 나쁘다.** 4배에서는 판면 아래 도형 위에 없는 상자를
만들었다 — 너무 키우면 판면 전체가 한눈에 안 들어와 국소 판단이 흐려진다.

그리고 배율이 바꾸는 것은 **몇 개를 잡느냐**뿐이다. **얼마나 정확히 긋느냐**
(맞은짝 IoU 0.81~0.83)는 배율과 무관하다. 위치를 아는 데는 글자꼴이 필요 없고,
「여기 규칙적인 잉크가 있다」면 충분하다.

## 라벨 규칙을 세 번 뒤집었다

조판 단위를 무엇으로 정할지가 계속 흔들렸다. 기록해 둔다.

**역할로** — 극장명 / 날짜 / 작품명 / 크레딧. 깨끗하게 갈리지만 독일어를 읽어야
한다. 낱말 사전을 붙여도 130개 중 60개가 「기타」로 빠졌다.

**틈만 본다** — 「줄들이 붙어 있고 둘레에 훨씬 넓은 틈이 있으면 한 덩어리.
안쪽 간격보다 두 배 넘게 벌어지면 끊는다.」 크기도 정렬도 안 본다.
1961 René Auberjonois 가 반례였다 — 여섯 줄의 크기도 정렬도 제각각인데 서로
붙어 있고 둘레가 167px 비어 있다. 크기를 기준에 두면 이런 판면이 조각난다.

**그런데 이 규칙이 배치를 망가뜨린다.** 제목과 본문의 틈이 안쪽 간격의 1.4배쯤인
경우가 흔해서(1961 Zürich plant und baut) 둘이 한 상자로 합쳐진다. 그러면 그
상자의 「행간」은 제목→본문 점프를 포함하고, 조판 측정이 무의미해진다.

크기 조항을 되살려 다시 찍어도 CV 는 1.080 → 1.085 로 움직이지 않았다.
**라벨 규칙이 원인이 아니었다.**

## 규칙 채택 기준의 결함

지금 기준은 「값이 모이는가(CV ≤ 0.30)」다. 그런데 무엇이 브로크만다운지를
재지 않는다.

진짜 배치 26장 대 무작위 배치 780장(같은 상자 크기, 자리만 섞음)으로 판별력을
쟀다. 지표 22개 중:

    AUC   지표              진짜    무작위
    0.79  왼쪽 축 공유       0.50    0.25   ★
    0.78  겹침(낮을수록)     0.000   0.008  ★
    0.70  아래 마진(낮게)    0.019   0.116
    0.70  오른쪽 마진(낮게)  0.025   0.087
    0.69  왼쪽 축 개수(적게) 3       4
    0.54  덮음 면적          0.103   0.103  ← 구분 못 함
    0.53  가로 무게중심      0.482   0.493  ← 구분 못 함

**덮음 면적은 CV 0.85 로 흩어지는데 무작위와도 구분이 안 된다** — 정보가 없는
지표다. **왼쪽 축 공유는 CV 0.45 로 흩어지는데 무작위와는 확실히 다르다** —
정보가 있는 지표다.

CV 는 「모이는가」를 재지 「브로크만답게 하는가」를 재지 않는다.

### 사람 상자 26장으로 두 기준을 견줘 보면

열네 지표 중 넷에서 정반대 답이 나온다.

    지표          CV     AUC    지금 기준   새 기준
    가로무게       0.26   0.50   제약       정보 없음   ← 잘못 채택
    외곽폭        0.23   0.68   제약       정보 없음   ← 잘못 채택
    축_왼쪽공유    0.45   0.79   자유       제약       ← 놓치던 것
    겹침          5.00   0.79   자유       제약       ← 놓치던 것

**가로무게**는 「활자가 가로로 평균 어디쯤 있나」다. 브로크만 0.482, 무작위
0.505. 무작위로 뿌려도 평균은 가운데로 가므로 산수지 디자인이 아니다. 그런데
값이 꽉 모이므로 지금 기준은 「브로크만은 활자를 가로 중앙에 둔다」를 규칙으로
채택한다.

**겹침**은 반대다. 브로크만은 정확히 0 이고 무작위는 0.010 이다. 진짜 규칙인데
CV 가 5.00 으로 최하위다 — 값이 전부 0 이면 평균도 0 이라 표준편차÷평균이
발산한다. **완벽하게 일관된 규칙을 「가장 흩어진 것」으로 읽는다.**

검출기 상자로는 이 넷이 전부 「자유」로 뭉개져 판정이 갈리는 것조차 볼 수 없다.
1.78배로 쪼개진 상자가 자리 지표를 모두 흔들기 때문이다 — **사람 상자가 필요한
이유가 여기 있다.**

### 그리고 지금 값이 좋아 보이는 이유

파이프라인이 낸 「행간/활자높이 CV 0.262」는 **작은 본문 27개만 재고 있었기
때문**이다. 사람 상자로 같은 것을 재면 75개가 잡히고 CV 0.700 이 된다.

세로 글씨(가로 행간이 의미 없음)와 x높이 3~4px(양자화 잡음)을 빼고 크기 계층으로
나누면 CV 0.13~0.28 로 돌아온다. **잘 잡을수록 규칙이 사라지는 역설**은 통을
안 나눠서 생긴 것이다.

## 생성 — 세 갈래로 시도해 셋 다 막혔다

**원본과 대조하기** — 같은 내용을 브로크만이 다시 만들어도 다르게 놓았을 것이므로
애초에 틀린 평가다. 실제로 조건 A(내용만) IoU 0.089, 조건 B(내용+측정 수치) 0.078
로 둘 다 0이고 수치를 준 쪽이 오히려 나빴다.

**골격 베끼기** — 사람 상자를 판면 골격으로 쓰고 내용만 갈아끼우면 포스터가
된다. 다만 색면과 그림을 원본에서 빌려오므로 베끼는 것이다. 좌표만 남기고
그림을 버리면 대부분 비어 보이고 자의적이다 — **색면이 하던 일이 컸다.**

**기하 최적화** — 판별력 있는 지표 일곱으로 목적함수를 만들어 담금질했다.
베끼지는 않지만 글자가 판면 밖으로 나가고, 개관시간이 제목보다 커진다.
크기가 자유변수인데 **무엇이 중요한지를 기하가 모르기 때문**이다.

## 역할을 넣으니 정리됐다

같은 최적화기에 역할별 상대 크기만 넣었다(실측: 제목 1.00 · 장소 0.65 ·
날짜 0.31 · 크레딧 0.13). 크레딧은 세로 0.77 에 묶었다 — 실측에서 자리가
고정인 유일한 역할이다(10~90% 0.75~0.79).

    아까                지금
    글자가 판면 밖        전부 안쪽
    개관시간이 제일 큼     제목이 제일 큼
    축이 허공에 뜸        왼쪽 정렬이 잡힘

기하 목적함수는 그대로다. **의미 정보 하나가 나머지를 정리했다.**

역할별로 자리는 여전히 안 정해진다(제목 x1 의 10~90% 가 0.02~0.68). **크기는
역할이 정하고 자리는 정하지 않는다.**

## 색면 — 문이 열렸다

파트 2 는 기울기 대역 지표를 「활자 블록 자체가 16~20% 로 사진과 겹친다」며
접었다. **활자 위치를 알고 빼면 겹치지 않는다.**

    결 있는 면적 (활자 상자를 가린 뒤)
      1957 Basler Privatbesitz (조각상 사진)   48%
      나머지 다섯 장                          2~7%

7배 차이로 갈린다. 순환을 피한 것이 이것이다 — 파트 2 에서 「글자를 빼고 나머지」가
순환이었던 이유는 글자 검출이 나빴기 때문이고, 지금은 사람/VLM 이 짚는다.

색면 자체도 잡힌다. 1970 Lohse 의 색 격자는 사각형도 0.99·0.86 으로 나온다.
다만 **bounding box 로는 표현이 안 된다.** 브로크만의 색면은 육각형·열쇠·불규칙
도형이고, 사각형으로 감싸면 정보가 사라진다(Kunststoffe 육각형 0.34).

모양까지 쓰려면 마스크가 필요하다. 아직 못 했다.

## 남은 것

    필요       사람 대 사람 일치도 — VLM 의 F1 0.90 을 해석할 기준이 없다
    필요       rules.py 채택 기준을 CV 에서 판별력으로
    안 됨      색면의 모양
    안 됨      활자 덩어리가 판면 «어디에» 앉는가 (마진 AUC 0.61~0.70)

「이 서버가 정하는 것은 세로 방향 조판뿐이다. 배치 판단은 하지 않는다」고
README 에 적어 두었다. 파트 3 이 확인한 것은 **배치야말로 브로크만다움의
대부분이고, 그것은 기하가 아니라 의미와 색면에 있다**는 것이다.
