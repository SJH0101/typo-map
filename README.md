# 조판 규칙 MCP 서버

포스터 디렉토리를 측정해 **규칙을 스스로 찾아내고**, 그 규칙으로 텍스트 배치를
계산·검사한다. 수치는 코드에 없다. 코퍼스에서 나온다.

브로크만 전용이 아니다. 호프만 포스터를 넣으면 호프만 규칙이 나온다.

**[문서 (PDF, 11쪽)](docs/typo-map.pdf)** — 무엇을 재는지, 어떻게 쓰는지,
InDesign 가이드 361개로 어떻게 검증했는지, 판본이 어떻게 올라왔는지.

## 설치

```bash
git clone https://github.com/SJH0101/typo-map.git
cd typo-map
pip install -r requirements.txt
claude mcp add typo -- python "$(pwd)/server.py"
```

Claude Desktop 이면 설정 파일에 아래를 넣는다.

```json
{"mcpServers": {"typo": {"command": "python", "args": ["/절대경로/typo-map/server.py"]}}}
```

## 업데이트

```bash
cd typo-map && git pull
```

경로가 그대로이므로 재등록할 필요가 없다.
측정 캐시는 `~/.typo-mcp/corpus.json` 에 저장되어 저장소 밖에 있으므로
`git pull` 로 덮이지 않는다. 위치는 `TYPO_MCP_CACHE` 환경변수로 바꿀 수 있다.

## 회귀 검사

측정을 고칠 때 「표본이 늘었다」만 보면 안 된다. 늘면서 이미 맞던 것이 깨질 수 있다.
`snapshot.py` 는 지금까지 고친 문제마다 대표 포스터를 하나씩 두고 측정값을 굳혀 둔다.

```bash
TYPO_MCP_CORPUS=/포스터/폴더 python snapshot.py           # 검사
TYPO_MCP_CORPUS=/포스터/폴더 python snapshot.py --bless   # 현재값으로 갱신
```

측정은 결정적이라 같은 입력에 같은 값이 나온다. 그래서 정확히 비교한다.
값이 달라졌다고 곧 틀린 것은 아니다. 무엇이 어떻게 달라졌는지, 그 포스터가
무엇을 지키려고 들어 있는지 함께 보여주므로, 눈으로 확인한 뒤 `--bless` 로 다시 굳힌다.

`GPU` 로 재려면 `TYPO_MCP_GPU=1` 을 준다. M 계열에서는 빠르지 않다 (mps 1.9 vs cpu 1.7s/장).

## 도구

### `measure_corpus`

```json
{"directory": "/포스터/폴더"}
```

폴더의 이미지를 전부 측정해 지표별 분포를 내고, **몰린 것만 규칙으로 채택**한다.

```
변동계수 <= 0.30  이고  표본 >= 20   →  제약
그 외                              →  자유 / 표본 부족
```

이 기준에는 결함이 있다. **「값이 모이는가」를 잴 뿐 「작가의 선택인가」를 재지
않는다.** 사람이 그린 상자 26장을 자리만 섞어 견주니 이렇게 갈렸다.

```
지표          AUC    CV      CV 판정    판별력 판정
겹침          0.79   5.00    자유       제약      ← CV 로는 최악, 실제로는 최강
축_왼쪽공유    0.79   0.45    자유       제약
외곽폭        0.68   0.23    제약       정보 없음  ← CV 로는 통과, 무작위와 구분 안 됨
가로무게       0.50   0.26    제약       정보 없음  ← 동전 던지기
```

### 셋째 기준 — 이 사람 것인가, 다들 그러나

값이 몰리고 무작위와 구별되어도, 그 값이 모든 작가에게 같으면 작가의 규칙이
아니다. 어센더/x높이는 네 코퍼스가 1.35~1.40 으로 똑같다 — 작가가 아니라
악치덴츠의 성질이다. 그런데 가장 안 흔들리므로 CV 기준에서 가장 먼저 채택된다.

코퍼스 4종 274장으로 재보니 기준이 뒤집혀 있었다.

| 지표 | 판정 | 설명력 | 귀무 | 배수 | |
|---|---|---|---|---|---|
| 색 수 | 자유 | 15.4% | 5.0% | 3.07x | **갈림** |
| 밝기 중앙값 | 자유 | 12.5% | 5.6% | 2.25x | 경계 |
| 좌 마진 | 자유 | 10.5% | 6.3% | 1.65x | 경계 |
| 최빈색 점유율 | **제약** | 9.9% | 5.2% | 1.91x | 경계 |
| 행간/활자높이 | **제약** | 1.5% | 6.2% | 0.25x | 공통 |
| 어센더/x높이 | **제약** | 0.4% | 0.8% | 0.46x | 공통 |

채택된 것은 작가를 못 가르고, 작가를 가르는 것은 전부 탈락해 있었다.
네 코퍼스를 가르는 지표는 결국 **하나뿐이고**(색 수) 그것도 색이다 —
스캔 조건을 읽고 있을 수 있으므로 `color_features` 의 경고를 함께 보라.

`distinct.py` 가 셋째 축을 잰다. 지표의 흩어짐 중 「어느 코퍼스냐」로
설명되는 몫을 코퍼스 딱지를 섞은 귀무모형과 견준다. 문턱 셋을 함께 쓴다.

- **귀무 분위** — 절대값으로 자르면 안 된다. 문턱이 지표마다 다르고,
  표본이 크면 우연히도 작게 나온다.
- **시험 횟수 보정** — 지표 17개를 각각 95분위로 자르면 하나쯤은 우연히
  통과한다 (1 − 0.95¹⁷ = 58%). 실제로 그랬다. 로제 코퍼스에 5장을 더
  넣자 어센더/x높이가 뒤집혔는데, 설명력은 0.57% 였고 중앙값 차이는
  1.375 대 1.396 이었다 — x높이 10px 측정에서 1.5% 차이다.
- **효과 크기** — 분위만으로는 「우연보다 크다」까지만 말한다. 설명력이
  귀무의 2배는 되어야 하고, 그 언저리는 「경계」로 따로 낸다. 최빈색
  점유율이 참조 순서에 따라 1.89~2.16 배로 흔들려 판정이 뒤집혔다.

**버리는 기준이 아니라 표시하는 축이다.** 「브로크만은 행간을 활자높이의
1.5배로 쓴다」는 호프만도 그래도 여전히 브로크만의 규칙이다. 채택은 앞의
둘로 하고, 셋째는 `scope` 로 «갈림/공통» 을 표시만 한다.

`measure_corpus` 에 `reference` 로 다른 작가의 캐시를 주면 함께 나온다.

```json
{"directory": "/포스터/폴더",
 "reference": {"호프만": "~/.typo-mcp/hofmann.json"}}
```

`discrim.py` 가 이 판별력을 잰다. 같은 상자를 자리만 섞은 배치를 귀무모형으로
두고 AUC 를 구한다. 자리에서 나오는 지표에만 쓸 수 있고, 행간비처럼 상자 안에서
나오는 값은 자리를 섞어도 안 변하므로 CV 판정을 그대로 쓴다.

「자유」로 판정된 항목은 검사도 배치도 하지 않는다.
표본이 늘면 다시 돌려서 재판정할 수 있다.

### `show_rules`

채택된 규칙과 탈락한 항목을 표본 수·변동계수와 함께 보여준다.

### `place_text`

활자 크기와 줄 수를 주면 행간과 베이스라인을 낸다.
모든 블록이 하나의 격자를 정수배로 공유하게 만든다.

### `check_layout`

배치안을 규칙과 대조해 위반을 돌려준다.

## 관계 지표 — 값이 아니라 「무엇이 함께 움직이는가」

값의 분포로는 네 작가가 거의 같다. 행간/활자높이 1.31~1.67, 어센더/x높이
1.35~1.40 — 학파가 공유하는 상수다. 갈리는 것은 관계였다.

| 마진–글자면적 결합도 | |
|---|---|
| **브로크만** | **0.210** ← 귀무 0.329~0.461 밖, **낮음** |
| 로제 | 0.342 |
| 루더 | 0.446 |
| 호프만 | 0.537 ← 귀무 0.326~0.467 밖, **높음** |

낮으면 **마진이 내용과 무관하다** — 마진이 먼저 정해지고 내용이 그 안에
담긴다. 격자 체계다. 높으면 마진이 구성의 결과다.

브로크만만 낮고 나머지 셋은 엮인다. 그리고 이것은 그가 『Grid Systems』
에서 주장한 그것이다. **값으로는 안 보이던 것이 관계로는 보인다.**

`features.py` 가 포스터를 이름 붙은 벡터로 만들고 `relate.py` 가 마디 묶음
사이의 순위 상관 절댓값 평균을 낸다. 결합도는 표본이 작을수록 커지므로
절대값으로 자르면 안 된다 — 작가 딱지를 섞은 귀무모형과 견준다.

못 잰 칸은 메우지 않는다. 중앙값으로 메우면 결측률이 코퍼스마다 달라 가짜
상관이 생긴다 — 마진 결측률이 로제 0%, 브로크만 25% 였을 때 그것만으로
선 네 개가 잘못 살아났다.

## 실제 결과 (프로젝트 포스터 44점)

```
채택   행간 / 활자높이    중앙 1.50   10~90% 1.30~1.83   CV 0.123  n=38
채택   어센더 / x높이     중앙 1.40   10~90% 1.15~1.50   CV 0.265  n=316
자유   여백 px                                          CV 0.34   n=38
자유   정렬선 수 / 블록 수                                CV 0.486  n=36
```

`asc_over_xh` 는 폰트의 성질이므로 규칙이라기보다 **측정 검산용**이다.
이 값이 1.4 에서 크게 벗어나는 블록은 측정이 깨진 것이다.

**검증** — 1958 Musica Viva 의 활자 크기와 줄 수만 넣었을 때
`place_text` 가 격자 14px, 본문 654/668/682…, 제목 661, 하단 738/752/766/780 을 냈다.
실제 포스터를 사람이 직접 찍은 값과 1px 차이다.

## 하지 않는 것

```
x 좌표 · 판면 마진 · 도형과의 관계   실측이 없다
활자 크기 비                       측정 오차가 지배한다
디센더                            검출 실패율이 높다
```

**이 서버가 정하는 것은 세로 방향 조판뿐이다.** 배치 판단은 하지 않는다.

## 구성

두 경로가 있고 이름으로 갈라 둔다. **재는 쪽**은 받은 자리를 재고, **비교
대상**은 스스로 훑어 찾는다. 의존은 한 방향이다 — `baseline/` 이 `measure/`
를 부르고, 그 반대는 없다.

```
server.py          JSON-RPC 전송과 디스패치. 50줄.
rules.py           원자료 → 분포 → 규칙 채택 판정
features.py        포스터 → 이름 붙은 숫자 벡터
relate.py          관계 지표 (무엇이 함께 움직이는가)
discrim.py         지표가 무작위 배치와 구별되는지 검사
distinct.py        지표가 작가를 가르는지 검사 (폰트 상수 거르기)
snapshot.py        측정 회귀 검사

measure/           재는 쪽 — 받은 자리를 잰다. 추정이 허용되지 않는다
    ink.py         잉크 프로파일 → 글줄·베이스라인·x높이·발음기호·디센더
    grid.py        베이스라인을 격자에 맞춰 본다 (측정값은 건드리지 않는다)
    region.py      상자 하나를 잰다. 잘렸으면 잘렸다고 말한다
    ground.py      짚어준 상자들 → 코퍼스 원자료

baseline/          비교 대상 — 스스로 훑어 찾는 자동 검출
    detect.py      단·줄·블록을 스스로 찾는다 (헛것 92 · 놓침 52)
    skew.py        회전각 검출
    scan.py        회전 보정 + 영역 검출 + 코퍼스 수집

color/             색 — 색 구성 지표와 색면 분할. 파트 2 가 여기서 자란다
    fields.py      features(색 다섯 숫자) · segment(색 계급 마스크)
    photo.py       사진이 있는지 판정 (선택. TYPO_MCP_PHOTO=1)

tools/             MCP 도구 — 스키마와 구현을 한 자리에
    grounding.py   measure_boxes
    corpus.py      measure_corpus · show_rules · style_card
    layout.py      place_text · check_layout
    shared.py      캐시 경로와 규칙 읽기
```

`measure/` 와 `rules.py` 는 numpy·scipy·Pillow 만으로 돈다. easyocr 는
`baseline/` 을 쓸 때만 필요하다 — 짚어서 재는 경로는 받지 않아도 된다.

## typographic metrology — 짚는 일과 재는 일을 나눈다

`baseline/` 은 판면을 스스로 훑어 덩어리를 찾고 그 안을 잰다. 두 일을 한
경로가 하므로 찾기가 틀리면 재기가 아무리 정확해도 소용이 없다.

오페라하우스 두 점을 IDML 가이드로 대조해 그 경계를 실측했다.

    덩어리 찾기   VLM 6/6 맞음      ·  baseline 은 17개·12개로 쪼갬
    상자 위치     VLM ±1px (8변 중 7)
    행간 재기     VLM +24% 편향     ·  measure/ 21.0px (정답 21px)
    정렬 판정     —                 ·  왼쪽 흩어짐 0.0px 대 오른쪽 39.6px

짚는 일은 추정이 허용되고 재는 일은 허용되지 않는다. 재는 값이 행간/활자높이
같은 비율이므로, 24% 편향은 규칙 채택을 통째로 바꾼다.

그래서 `measure/` 를 따로 둔다. 상자를 받아 그 안만 재므로 도형을 글자로
오인하거나 검은 바탕의 흰 글자를 놓치는 실패가 구조적으로 생기지 않는다.

```python
from measure.region import measure
measure(path, (x1, y1, x2, y2))
# → baselines · x_heights · lead · lead_over_xh · align · align_spread
```

### 짚는 쪽은 누구인가 — `measure_boxes`

API 키가 필요하지 않다. 이 저장소가 MCP 서버이므로 **클로드가 클라이언트로
붙어 짚는 쪽을 맡는다.** 포스터를 눈으로 보고 상자를 불러주면 서버가 그 안을
잰다. 모델을 코드 안에서 부르는 것이 아니라, 모델이 코드를 부른다.

```json
{"image": "/포스터.jpg", "store": true,
 "boxes": [{"id": "제목", "role": "제목", "box": [0.02, 0.27, 0.31, 0.31]}]}
```

좌표는 판면 대비 0~1 비율이 기본이다. 모델은 픽셀을 세지 않고 비율로 보므로
원본 해상도를 알려주지 않아도 상자를 부를 수 있다.

`store: true` 면 짚어준 상자만으로 코퍼스가 쌓이고 규칙이 다시 뽑힌다. 이
코퍼스는 `measure_corpus` 의 것과 **캐시를 나눠 둔다** — 자동 검출한 분포와
섞으면 규칙이 어느 방법에서 나왔는지 말할 수 없다. 모든 도구가 `cache` 인자로
볼 코퍼스를 고를 수 있다.

1957 Musica Viva 를 짚어 재니 네 덩어리가 전부 행간 17.0px 로 나왔다 —
블록이 공유하는 베이스라인 격자가 측정으로 드러난다.

`clipped` 는 잉크가 상자 가장자리에 닿았는지 알려준다. 이 파일은 받은 상자
안만 보므로, 상자가 글자를 가로지르면 밖에 남은 부분을 볼 방법이 없고 잘린
값을 아무 말 없이 돌려주게 된다. `PAD` 가 판정 여유가 된다 — 제대로 짚은
상자는 잉크와 창 사이가 비어 있으므로 가장자리에 닿지 않는다.
`["right"]` 가 나오면 상자를 넓혀 다시 부르면 된다.

상자는 **잉크 전체**다 — 발음기호 위끝부터 디센더 아래끝까지. 캡 높이~
베이스라인으로 잡으면 ü 의 점과 j 의 꼬리가 밖으로 나가고, 마진과 덮음
면적이 그만큼 작게 나온다.

한계는 짚는 쪽에 있다. 상자가 색면을 물면 그 색면이 잉크로 잡히고 (8줄 →
1줄), 상자가 짧으면 마지막 줄이 빠진다. 재는 쪽은 받은 자리를 정확히 재므로
틀리면 상자가 틀린 것이다.

의존: `requirements.txt` 참고

## 코퍼스를 바꿀 때

`measure_corpus` 를 다른 폴더로 다시 돌리면 캐시가 통째로 갈린다.
여러 코퍼스를 오가려면 `TYPO_MCP_CACHE` 를 따로 지정한다.

```bash
TYPO_MCP_CACHE=~/.typo-mcp/hofmann.json claude mcp add hofmann -- python /경로/server.py
```

## 작가를 늘리기

폴더 하나면 된다. `add_designer` 가 측정·규칙 채택·뇌 만들기를 한 번에 한다.

```json
{"name": "켈러", "directory": "/포스터/켈러"}
```

포스터가 적으면 선을 못 잰다 — 마디 15개를 서로 붙들고 재려면 45장은
있어야 한다. 그때는 `warning` 으로 알린다. **선이 0개인 것과 못 잰 것은
다르다.** `list_brains` 로 만들어 둔 뇌를 본다.

뷰어는 `brain-*.json` 을 전부 주우므로 늘린 작가가 그대로 들어온다. 목록으로
보여 주고 여덟 명이 넘으면 찾기 상자가 붙는다. 판은 넷까지 나란히 놓는다.

코퍼스를 합쳐 보려면 `pool_brains` 를 쓴다. 한 작가로는 표본이 모자라 안
보이던 관계가 합치면 보일 수 있다 — 다만 그냥 합치면 작가별 값 수준 차이가
가짜 선을 만들므로 코퍼스마다 제 안에서 순위를 매긴 뒤 합쳐서 잰다. 합친
뇌는 작가가 아니므로 뷰어 기본 목록에서 빠진다 (`build.py --all` 로 넣는다).

## 책이 말한 규칙을 그의 포스터로 검사한다

브로크만은 『Grid Systems』 에서 규칙을 스스로 적어 두었다 (`docs/BROCKMANN_RULES.md`).
규칙 문서와 잰 코퍼스가 둘 다 있으니 물을 수 있다 — **그의 포스터가 그의 규칙을
지키는가.** `booktest.py` 가 검사한다.

| 규칙 | 범위 | 판정 | |
|---|---|---|---|
| R1 단 폭 ∝ 활자 크기 | 책 | 반대로 간다 | 포스터 안에서 r = −0.315 |
| C1 행당 7~10 낱말 | 책 | 안 지킨다 | 중앙 3.5낱말, 구간 안 9% |
| R2 행간을 서로 맞춘다 | 둘 다 | **지킨다** | 벗어남 2.4% 대 귀무 7.3% |

**판정을 읽기 전에 범위를 보라.** 책의 상당수는 서적·브로슈어 규칙이고 (C3 이
「서적·브로슈어·카탈로그」라고 못 박는다), 그것을 포스터에 대고 재면 범주 오류다.
R1 의 근거인 「행 전환 피로」는 여러 행을 연속으로 읽을 때 얘기다. 어긋난 것이
아니라 다른 물건에 대고 잰 것이다.

R2 는 포스터에도 걸린다. 1959 Juni-Festwochen 의 행간이 `[22.0, 11.0, 11.0]` —
11px 단위의 정확히 2배와 1배다.

검사할 수 없는 규칙은 이유와 함께 남긴다 — 「중요도」·「고요함」·「균형」은
정의가 사람 쪽에 있고, 서체 식별과 필드 검출은 아직 못 한다.

넷 중 하나로 끝나는 구조다. 말했고 지킨다 · 말했는데 안 지킨다 · **안 말했는데
그런다** · 안 말했고 안 그런다. 셋째 칸이 암묵지고, 마인드맵의 선이 거기 산다.

## 뇌 뷰어

`viewer/` 에 있다. `python viewer/build.py` 로 한 파일 HTML 을 굽는다 —
CSP 때문에 바깥에서 아무것도 못 불러오므로 뇌 데이터까지 안에 박는다.

작가를 여러 개 고르면 판을 갈라 나란히 놓는다. 마디 배치는 하나만 만들어
모든 판이 같은 자리를 쓰므로, 왼쪽 「덮음」에서 오른쪽 「덮음」으로 눈이
바로 건너간다. 고른 뇌 모두에 있는 선은 회색으로 물러나고 한쪽에만 있는
선이 색을 얻는다.
